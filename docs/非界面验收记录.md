## 环境与方法

- Windows，Dart **3.14.0 stable windows_x64**，Go **1.27.4 windows/amd64**，Git **2.55.0.windows.1**。
- 所有服务仅数字环回地址；全部账号、密码和令牌均为测试专用。Git 使用临时本机裸仓库，不连接真实 GitHub/Gitee、不创建远端、不 push 本项目。
- Dart 包分别 `pub get / format / analyze / test`，不是只跑静态检查；系统 SDK 未写入 PATH，便携工具/缓存放本机忽略目录。下载压缩包已回收。
- 快速 KDF 只用于测试；产品初始化默认64MiB/3轮，不拿测试值冒充安全参数。

## 实际端到端场景

1. 新建本机根账号，签名公开名册；第二个独立账号生成加入请求，根账户确认后按外部指纹和逐修订签名接受账号、设备与控制密钥。
2. 两个专用同步目录连接同一个真实裸Git仓库，分别写自己的设备分支；对端拿原始签名密文，不重新生成消息ID或改变作者。
3. 频道创建、第二账号自助加入、成员签发新epoch公告与逐接收者密钥封装，之后普通消息可解。Git日志不含测试聊天正文。
4. 同内核固定机器人用OneBot11和12分别发消息；对端仍识别机器人身份。成功返回前日志已flush；11 ID映射同步落盘，立即关闭再打开后旧整数ID仍对应原生同一MessageRecord。
5. HTTP+WS自报owner/其他bot/self、读取owner专属私聊、缺好友关系发私聊均被拒绝，失败不产生额外持久消息。
6. 真实接收端先import原密文，未refresh不伪推业务事件；refresh后WS/轮询得到同ID消息，重复import/refresh不重复推送。
7. 新人只得到加入后的新期次；用新key bytes伪装旧epoch，对旧正文实际AES-GCM认证失败。退群者能继续解自己已获旧历史，拿旧key伪装新epoch仍认证失败。
8. 同副本8个并发ensure只生成一次期次；同epoch不同key/授权公告锁止，不擅自挑一把继续。
9. 晚到grant在一次open/refresh内补重放早先合法正文；签名有效但AEAD不符的坏事件隔离，不堵死全部正常消息。
10. 根名册增加第三账号后，从磁盘重开，旧public/private朋友圈按当时名册重放；新public期次含新人，private key不交给第三人。
11. Node在没有中继、初始中继不通或之后中继进程消失时继续定时Git；订阅超过64个scope明确关闭中继降级，不截掉部分topic伪称完整。
12. 临时仓库包含恶意hooks/配置/路径/可执行文件/symlink/gitlink时拒绝，不checkout远端或执行hook；已见main/device历史回退、分叉和删除被拒。
13. 文件日志锁经真实第二进程验证；部分append/flush失败后停止继续写，close可并发等待释放。不能把这等同于断电耐久测试。
14. 本地bot草案保存在本机签名加密私密资料，不追加到设备事件、不进Git/中继；入驻才生成公开register命令，配额失败保留草案。

## 复验入口

各Dart包目录执行：

```text
dart pub get
dart format --output=none --set-exit-if-changed lib test
dart analyze
dart test --reporter expanded
```

runtime另检查 `bin`，Dart中继另检查 `example`。Go模块目录执行：

```text
go test ./... -count=1 -cover -timeout=90s
go vet ./...
go build ./...
```

使用 [本机检查脚本](<../tools/check.ps1>) 可批量跑包级检查；脚本经语法检查，当前宿主拒绝直接执行部分PowerShell脚本，实际验收逐包调用上述SDK命令完成，没有改变执行策略。互通使用 [工具说明](<../tools/relay_interop/README.md>) 中的直接命令。

更多运行方法见 [runtime说明](<../packages/runtime/README.md>)，真实支持动作见 [OneBot矩阵](<../packages/onebot/README.md>)，安全边界见 [当前架构](<当前架构与实现边界.md>)。
