# 在座简版测试前端

此轮只添加前端及其适配控制器，不修改 core/domain/runtime 的加密、授权或同步协议。沿用 [mobile_probe 应用](../apps/mobile_probe/README.md)，默认入口已从开发探针切换为简版聊天页面；原图片/Git 验证页在“关于”中保留。

## 可以测试什么

- 创建本机账户、密码解锁与锁定；首次创建可导入社区公开 JSON，并单独核对仓库外根指纹。
- 新建公开空间、按空间 ID 加入、会话列表和文字聊天；茶会及机器人私聊旁观者只读。
- 添加好友并创建私聊；复制公开社区、指纹、签名加入请求；社区创建者粘贴加入请求接纳。
- 图片发送与点击读取，使用真实媒体加密/授权投影；Android 使用系统图片选择器，桌面暂用显式输入本机文件路径（最多8MiB）。没有任意 URL 下载，也不把远端文件名当输出路径。
- 设置 Git 远端与手动同步；桌面复用系统 Git 凭据助手，Android 复用嵌入式 libgit2 和 Keystore 包裹 PAT。启动不联网，不自动打开 OneBot 服务。
- 查看 Git 配置/同步错误/本机状态，以及项目与第三方许可。

当前不做复杂管理后台、朋友圈/论坛页面、通知、后台保活、自动同步、文件选择器完善或正式账户恢复。输入框保存在内存，锁定/关闭/切换会话会丢失未发送草稿。消息发送成功仅代表本机加密日志落盘，不表示远端或对方已收到。

## 最短测试流程

1. 创建测试账号（账户名1–14位小写字母/数字/下划线）；密码12–1024位，须含大写与小写字母、不能含账户名或常见弱模式（如123456/password），记住密码。新版本在任何资料写入前验证；旧版本可能留下只有公开初始化文件的半成品目录，新版会明确提示并保留，不能将它误认为完整账号，也不自动删除。新建空间，发送文字，锁定后重新解锁确认历史保留。
2. 在“设置与同步”填入独立的测试 Git 仓库地址并连接，再点击手动同步。不要使用本项目源码仓库当聊天传输仓库。
3. 邀请另一名测试者：创建者复制公开社区 JSON 与指纹；对方从仓库外核对指纹后在首次创建界面导入，创建自己的账号并复制加入请求。
4. 创建者粘贴并接纳加入请求，然后同步；对方配置同一仓库并同步，获接纳后加入空间，再同步；创建者再拉取一次成员变更。
5. 双方各发送文字/图片后手动同步，另一方同步读取。若成员变化触发新会话密钥，可能需要合法持钥成员再同步一轮以分发新 epoch；错误不可当发送成功忽略。

## 可选 HTTPS 令牌（ui-test4）

设置页可填写 HTTPS 用户名与访问令牌 PAT：
- 不填且不选“使用已保存令牌”：桌面沿用系统 Git 凭据助手/匿名；Android 匿名 HTTPS，不再强制先保存 PAT。
- 填写但不勾“加密保存在本机”：只在当前已打开 Git 后端的内存使用，锁定/断开/关闭后释放引用；不写URL、argv、Gitconfig或资料。Dart字符串无法保证内存即时清零。
- 勾选保存：Windows 使用当前用户 DPAPI，Android 使用已有 Keystore；按完整HTTPS仓库+用户名范围存储。不会明文保存；移动便携目录到另一台电脑/Windows用户后不能保证解密，需重新输入。
- 下次打开应用需再次填写同仓库和用户名并显式勾选“使用此仓库已保存的令牌”，不会自动读取主机其他账号。清除按钮删除该范围并断开当前Git后端，防旧令牌继续复用；远端令牌撤销仍需到Git托管服务管理。
- GitHub 可用自己的用户名或 x-access-token；fine-grained PAT 须选中目标测试仓库并给予 **Contents: Read and write**（只给 Read 时读能成功、push 会返回 `remote: Write access to repository not granted` 并映射为 `permission_denied`）。仓库保护/组织策略可能另行限制；令牌不授予本来没有的访问权。不要把令牌贴在仓库URL、聊天或截图里；已在聊天/截图暴露的令牌应立即撤销重发。
- 显式令牌只允许HTTPS，禁止重定向；子进程临时环境传递认证header，同用户/高权限进程可读取环境，这是本机同用户信任边界，不是OS隔离沙箱。TLS校验保持开启。

不要使用真实业务资料做默认测试。

## 构建版本与社区同步诊断（ui-test9）

- 右上角显示编译时嵌入的 `测试版 · ui-test9`；目录名称不代表实际运行版本。此次核验发现一份名为test8的已解压目录中 `data/app.so` 与test4完全相同，而原test8压缩包本身正确。原因尚未确定，不推断是谁覆盖了文件。
- 新打包脚本 `tools/package/stage-flutter-windows.py` 使用新版本目录、拒绝覆盖，校验构建→打包目录→压缩包→临时重新解压逐文件SHA256，包内附BUILD.json、SHA256SUMS与对应源码信息。不把用户资料复制进包。
- **令牌能推送不等于可以加入一个在座社区。** 创建本机账号且不导入社区时会生成独立社区根；不能仅填已有另一社区的Git地址就替换其身份。`community_fingerprint_mismatch` 表示远端签名根与本机确认值不同。必须停止同步，不自动修改本机指纹、不覆盖main、不删除已有资料。
- 要使用现有本机社区：由用户选择新的、完全空的独立仓库绑定；不要给新仓库预加README。要加入已有远端社区：先在仓库外核对其公开配置及根指纹，再用单独新资料目录创建加入账号，由原社区创建者接纳；当前没有自动合并/迁移已有本机账号或会话的功能。
- `invalid_manifest_tree` 表示远端main不是规范在座社区配置（例如只有README）；`invalid_manifest_signature` 表示签名/版本链验证失败。界面保留这些固定码，不再兜底为operation_failed，也不让异步错误流覆盖成git_failed。
- 不要为了“修复”同步直接删除信任记录、修改指纹、强推main。旧资料应原样保留；同一资料目录不能由多个客户端同时打开。

## Windows长路径与安全升级（ui-test10）

- 已复现：便携资料的受管Git路径长约152字符时，首次发布设备分支前的同步可成功；其后拉取 `refs/zaizuo-incoming/<24hex>/<64hex>.lock` 的完整路径会达273字符，Git默认Windows路径限制报 `cannot lock ref ... Filename too long`。远端可能已经收到本轮推送，但回读验证失败，客户端不能把整轮标记成功。
- Windows `GitCliBackend` 现仅对子进程附加 `-c core.longpaths=true`；不写全局/受管Gitconfig、不改注册表或系统安全策略，原pins/checkpoint/签名检查保持不变。若仍遇超长路径会显示固定 `git_path_too_long`，不显示本机原路径或令牌。
- **`data/` 是Flutter运行代码，不是用户资料；不要把旧版本的data覆盖到新版。** 当前便携账号目录是 `zaizuo-data/`。新包应解压到新的干净程序目录，用 `--data-dir=<原资料绝对目录>` 继续使用原资料，不必搬动、重建或修改指纹。打开同一资料前必须先退出旧实例。
- 包内 `start-verified.cmd` / `verify-and-start.ps1` 先按打包时内置文件清单和SHA256核对程序，校验失败就拒绝启动。`-VerifyOnly` 只做只读检查；`-DataDirectory` 仅传入原资料路径，不读取/移动账号文件。校验清单防误覆盖，不等于签名发行或抵御同用户恶意同时替换清单和程序。

## 代理与网络容错（ui-test6）

观察到本机GitHub中转链路曾返回502，随后用 `http.version=HTTP/1.1` 的重试推送成功。这只能证明一次重试成功，尚未通过对照实验确认502由HTTP/2或Steam++中转自身引起。

客户端对此的处理：
- 网络操作失败且诊断为网关错误（502/503/504）时，自动用 HTTP/1.1 重试一次，再报告固定码 `remote_gateway_failed`。
- 其他错误仍按认证/权限/仓库/TLS/网络分类；界面只显示固定中文提示和稳定代码，不显示远端原文、URL 或令牌。

若仍失败，需结合固定错误码区分网络、认证、社区指纹、历史检查点等原因。第三方加速工具的配置与可用性不由本项目保证，不修改其二进制；SSH（ssh.github.com:443）是可选通道，但是否绕开代理以及身份/主机密钥是否可用必须单独验证，不能只凭TCP可达保证同步。

## 数据与平台

- 默认目录为应用支持目录下的 client；Android 为 getNoBackupFilesDir 的 client 子目录。账号资料与受管 Git 仓库分离，绝不能将整个资料目录 git add。
- 默认目录创建失败时显示固定类别和 Windows 错误码/本机目标路径，不再将所有异常误报为权限。启动页提供重试与用户明确选择“使用程序旁的便携资料目录”：选择后使用 exe 旁的 `zaizuo-data`，不修改权限、不提权、不自动搬动已有资料。便携包应解压在自己可写且非共享的持久目录。
- 桌面入口支持 `--data-dir=<绝对目录>`，便于同机两个实例使用不同测试目录。禁止两个实例同时打开同一资料目录；当前前端不提供跨进程资料排他锁。
- 测试资料沿用 LocalProfile 原型：本机解锁因素与资料同目录，不是独立账号第二因素保护。Keystore 保护的是 Git PAT，不等于整个账号保险箱已完成安全产品化。
- Windows/Linux 平台宿主已生成，Linux 本轮未构建。Windows 首次构建缺插件 symlink 特权；经维护者明确授权单次管理员构建后 Debug 构建成功，系统开发者模式原本已开，未改 ACL/执行策略或持久安全策略。随后普通权限 Release 构建成功，Release exe 已普通权限启动并截图确认欢迎界面可读；未把 Widget 测试冒充桌面双窗口点击收发验收。Windows 日常运行不需管理员，Git 同步需本机已安装系统 Git。
- Android arm64 debug 包可本机构建，安装/运行和手机实际联网仍须真机验收。开发包非正式签名，不覆盖旧 Release，不自动发布。
