# 在座 CLI 构建与安装（Windows / Linux）

本页面向**非界面 CLI**测试包，不是Flutter桌面界面或正式稳定版。原创代码采用 [AGPL-3.0-only](../LICENSE)；第三方依赖保留各自许可。经维护者明确授权，源码及附带项目许可/对应源码地址的测试包在[GitHub预发布页](https://github.com/bomomoQWQ/zaizuo/releases/tag/v0.1.0-media-test3)提供。打包脚本本身不赋予新项目开源许可、不创建远端、不commit/push、不修改系统PATH/防火墙/执行策略，也不安装系统服务。

## 构建产物

| 平台/模式 | 产物 | 用户需安装Dart SDK？ | 当前说明 |
| --- | --- | --- | --- |
| Windows x64 `Snapshot` | zip：launcher + `dartaotruntime.exe` + `zaizuo.aot` +配置模板/文档/许可证/摘要 | 不需要 | **AOT快照+配套运行时**，不是单文件在座EXE；避开已复现的gen_snapshot绝对Unicode参数问题 |
| Windows x64 `Exe` | zip：标准 `dart compile exe`生成的原生可执行文件+launcher与文档 | 不需要 | 本机标准编译曾失败；脚本失败立即停止，不用snapshot伪称EXE |

| Debian/Ubuntu x64/arm64 | `.deb`（可选） | 不需要 | `dpkg-deb --root-owner-group`无root生成，系统安装是否提权由用户明确决定 |

每个包只收集显式新stage内容，不拷贝工作区、账号资料、Git仓库、`.local/`、缓存或当前环境变量。包内`BUILD.json`只记录版本、架构、构建模式/SDK，不记录用户名、口令、token、完整宿主路径；每包有SHA256。摘要检验传输完整性，不代替可信发布签名。

## 前提

- 构建机：Dart SDK（本轮Windows诊断实际为**3.14.0 stable windows_x64**），所有本地Dart包先能通过`pub get / analyze / test`。SDK可留项目`.local/`，不改系统PATH。
- Windows：PowerShell5.1或更高；本项目脚本以UTF-8 BOM保存兼容5.1中文注释；zip由`Compress-Archive`生成。执行策略阻止脚本时先报告具体策略，**不建议`-ExecutionPolicy Bypass`、关闭杀毒或管理员重跑**。
- Linux：Bash、tar/gzip、sha256sum、coreutils。要生成deb需`dpkg-deb`；脚本不会自动sudo安装缺失工具。
- Git只在同步时需要；默认媒体编码采用AOT内置纯Dart codec，cwebp只在显式native备用编码路径需要。二者不捆在包内，系统安装/可信便携版由使用者管理，不与在座账号密码混用。
- Windows包默认x64；Linux脚本只识别x86_64/aarch64。本页没有跨架构模拟、Alpine/musl或所有旧glibc兼容验收。

## Windows：显式构建便携snapshot包

从项目根目录运行（路径可含中文；脚本不移动源码或SDK）：

```powershell
.\tools\package\build-windows.ps1 `
  -DartExe "$PWD\.local\dart-sdk\bin\dart.exe" `
  -OutDir "$PWD\dist\packages" `
  -Version '0.1.0-media-test2' `
  -Mode Snapshot
```

- 默认Dart路径为根目录`.local/dart-sdk/bin/dart.exe`，默认输出`dist/packages/`。脚本保留随机新建的`.local/package-build/<id>/`中间文件用于诊断，不自动递归删除。
- 默认执行`pub get --enforce-lockfile`，防打包时无意升级依赖；若同一副本已由父流程准备依赖，可显式`-SkipPubGet`。
- 默认执行包内`--help`烟测；`-SkipSmoke`仅用于受控交叉检查，`BUILD.json`会标未测，不能据此宣称可运行。
- 已存在同版本zip拒绝覆盖。修改版本或由使用者明确处理旧产物；脚本不自动删旧包。
- 选择`-Mode Exe`才会走标准`dart compile exe`。若失败，不自动换Mode、换目录、抬权限或更改SDK。

### 本机脚本策略与实际证据

本次宿主直接执行PS1得到`AuthorizationManager check failed / PSSecurityException`。**没有使用ExecutionPolicy Bypass、Invoke-Expression、换shell、抬权限或修改系统策略**；PS1只做AST语法检查，不能声称整脚本已运行。按用户单独授权，实际采用已允许的native构建命令与手工显式allowlist组装zip：完整CLI AOT快照、包内launcher、zip解压后launcher均`--help`成功，64个包内摘要核对通过。baseline包约4.34MB，仅是流水线启动验收，最终媒体CLI变更后必须重新构建，不拿旧baseline冒充新功能包。媒体测试版另已从解压包真实执行默认KDF初始化/重开、1KiB文件逐字节往返、PNG→默认WebP编码、messages与明确路径download；这不等于跨机或大文件压力测试。可用[包级烟测工具](<../tools/package/smoke_package.dart>)复验。

实际native命令骨架（在同一个诊断工作目录执行，使用参数数组避免PowerShell把`-D`误拆）：

```powershell
# $sdk/$repo 为可信绝对目录；$work 为本仓库.local内已有新诊断目录。
# 不执行受阻PS1，不从网络脚本文本求值。
Push-Location $work
try {
  $compilerArgs = @(
    "$sdk\bin\snapshots\gen_kernel_aot.dart.snapshot",
    '--platform', "$sdk\lib\_internal\vm_platform_product.dill",
    '--packages', "$repo\packages\runtime\.dart_tool\package_config.json",
    '--aot', '--no-embed-sources', '--target-os', 'windows',
    '-Ddart.vm.product=true', '--output', 'program.dill',
    "$repo\packages\runtime\bin\zaizuo.dart"
  )
  & "$sdk\bin\dartaotruntime.exe" @compilerArgs
  if ($LASTEXITCODE -ne 0) { throw 'AOT kernel failed' }
  & "$sdk\bin\utils\gen_snapshot.exe" --snapshot_kind=app-aot-elf --elf=zaizuo.aot program.dill
  if ($LASTEXITCODE -ne 0) { throw 'AOT snapshot failed' }
  & "$sdk\bin\dartaotruntime.exe" zaizuo.aot --help
} finally { Pop-Location }
```

### Windows AOT失败诊断记录

此前验收只记录“临时program.dill读不到”；本轮在**同一F盘中文工作区、同一SDK**进一步分离阶段，未改系统ACL：

1. 隔离当前子进程`PUB_CACHE / TEMP / TMP / APPDATA / LOCALAPPDATA / DART_SUPPRESS_ANALYTICS`到项目`.local/`，标准`dart --verbose compile exe`仍exit254：`Unable to read file ...program.dill`。
2. 显式`dart compile kernel`成功产生约6.5MB kernel，PowerShell可读同一文件；`gen_snapshot`用绝对中文文件名时显示乱码路径并exit255。
3. `gen_snapshot`改为**同一目录cwd下相对ASCII文件名**可读kernel；普通kernel不是AOT，故第一次诊断出现缺TFA的明确错误（不是最终CLI构建成功）。
4. 用Dart SDK的`gen_kernel_aot.dart.snapshot --aot`生成正确AOT kernel，再以同目录相对`program.dill / --elf=zaizuo.aot`调用`gen_snapshot`，独立探针已成功由配套`dartaotruntime.exe`执行。

这为**Windows gen_snapshot命令行Unicode参数缺陷**提供复现证据，不能据此宣称所有“读取失败”都是编码问题。此次调用没有ACL denial；后续若出现`Access denied / 拒绝访问`必须停止并报告，不换路径规避权限、不改系统安全策略。完整本机诊断日志留`.local/package-diagnostics/`，不进入发布包。

snapshot脚本使用上述显式pipeline，源码和SDK仍留原位置，仅把native generator需要的**输出参数**改为相对ASCII，属于工具兼容诊断，不是权限绕过。内部编译工具接口可能随SDK变化；当前测试以3.14为准。参考实际SDK实现：[Dart3.14 compile命令](<https://github.com/dart-lang/sdk/blob/3.14.0/pkg/dartdev/lib/src/commands/compile.dart>)、[AOT生成步骤](<https://github.com/dart-lang/sdk/blob/3.14.0/pkg/dart2native/lib/generate.dart>)。没有复制SDK实现或修改SDK文件。

## Linux：原生tar.gz与可选deb

在Linux本机的项目根目录运行，Dart路径和输出均可配置。本轮由父流程在已授权Ubuntu **24.04.4 / Git2.43.0 / Dart3.14.0**真实执行此脚本，exit0，原生CLI的`--help`含媒体子命令，portable tar.gz与`.deb`均已生成。父流程随后真实验证tar.gz解压、包内全部SHA256与launcher `--help`，以及`dpkg-deb -x`无root提取后的`usr/bin/zaizuo --help`，均exit0，未系统安装、未sudo。本子任务不自行SSH或修改远端系统。每次后续安全patch仍需重新编包，不能把旧binary当新源码验收。

```sh
bash tools/package/build-linux.sh \
  --dart /absolute/path/to/dart-sdk/bin/dart \
  --out-dir "$PWD/dist/packages" \
  --version 0.1.0-media-test2 \
  --deb auto
```

- `--deb auto`：有dpkg-deb则生成；没有则仅tar.gz并明确说明。
- `--deb yes`：没有dpkg-deb就失败，已成功的tar.gz保留；不会自动安装依赖。
- `--deb no`：只portable。
- `--skip-pub-get`、`--skip-smoke`是显式受控开关；正常分发不要跳烟测。
- 当前子进程HOME/XDG/TMPDIR/PUB_CACHE隔离到项目`.local/`；不修改登录用户配置，不把真实环境变量写入产物。
- 不要求root，不执行sudo，不自动建立systemd服务，不改用户账户或默认端口。

Linux x64输出示意：

```text
zaizuo-cli-0.1.0-media-test2-linux-x64.tar.gz
zaizuo-cli-0.1.0-media-test2-linux-x64.tar.gz.sha256
zaizuo-cli_0.1.0-media-test2_amd64.deb
zaizuo-cli_0.1.0-media-test2_amd64.deb.sha256
```

deb依赖声明为libc6/libgcc-s1/libstdc++6/git，不要求webp；这是依赖提示，不代表所有最低动态库版本已兼容。应在准备分发的目标Ubuntu/Debian版实际`--help`、初始化、跨机同步与媒体收发验证。构建于新glibc的binary不能承诺在任意旧系统运行。

## 安装/解压（不自动执行）

### Windows免管理员

在有写权限的目录解压，确认外层zip SHA256；进入包含launcher的目录执行：

```powershell
.\zaizuo.cmd --help
```

保留整个snapshot目录，不单独搬走`.aot`或换其他版本runtime。无需Dart SDK，不自动下载Git/cwebp。系统安全保护拦截时保留证据与具体错误，不关闭保护当默认安装步骤。

### Linux portable无root

```sh
sha256sum -c zaizuo-cli-0.1.0-media-test2-linux-x64.tar.gz.sha256
mkdir -p "$HOME/.local/opt"
tar -xzf zaizuo-cli-0.1.0-media-test2-linux-x64.tar.gz -C "$HOME/.local/opt"
"$HOME/.local/opt/zaizuo-cli-0.1.0-media-test2-linux-x64/zaizuo" --help
```

包内可再执行`sha256sum -c SHA256SUMS`。不自动将目录加入PATH。

### Linux deb

系统安装须由用户在目标机明确执行本机包管理器；该步骤需要管理员权限并可能安装依赖，打包脚本本身不执行。本包无preinst/postinst脚本。

无root也可只解包到用户目录：

```sh
mkdir -p "$HOME/.local/opt/zaizuo-deb-test"
dpkg-deb -x ./zaizuo-cli_0.1.0-media-test2_amd64.deb "$HOME/.local/opt/zaizuo-deb-test"
"$HOME/.local/opt/zaizuo-deb-test/usr/bin/zaizuo" --help
```

launcher通过自身位置计算prefix，支持上述非系统解包。卸载程序不得自动删除账号资料；资料清理/恢复另行明确决定。
