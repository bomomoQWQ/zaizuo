## 使用边界

维护者需要继续使用电脑，因此停止了宿主鼠标/键盘/焦点及实际窗口自动化；不会将后台无头测试称作完整 Windows EXE 黑盒通过。未连接业务远端、未读取用户密码或私钥，未改用户资料、Windows 权限或安全策略。

## 复现与修复

- 用户报告创建账号返回 operation_failed。截图无法证明密码是否合规，不能据此判断用户输错密码。
- 代码核查及回归复现确认：旧 LocalProfile 在 PasswordVault.seal 检查密码前已写 community.json/trust.fingerprint，密码不合规会留下非空半成品目录；前端将 FormatException 和后续非空目录错误压成同一个 operation_failed。
- runtime 现先校验账户名/显示名称/密码，再创建目录、生成密钥或写文件。前端同时预校验，显示固定的 invalid_account_name/invalid_display_name/invalid_password；密码规则在输入框显示，不回显输入，不放宽安全规则。
- 对既有完整资料提示解锁；既有不完整目录提示 incomplete_profile 并保留原文件，不静默覆盖或删除。不能承诺任意断电/磁盘故障下创建事务已原子化。

## 已实际执行

1. runtime 回归：无效密码不留下文件；有效创建、密码解锁、密文资料防篡改、重启回放。2项通过。
2. 前端 controller：无效密码拒绝且不创建 profile；相同目录更正后可创建；半成品标记文件保持字节不变。
3. 无头 Widget 用户流程：真实填写账户名、显示名称、密码和确认密码→点创建，验证错误密码提示→更正为一次性测试密码→真实创建账号→点新建空间/创建→输入消息并点发送→打开设置点“锁定本机资料”→错误密码解锁被拒→正确密码点“解锁”→点击会话历史仍在→销毁旧控制器和界面，建立全新实例→再次通过密码框和解锁按钮打开，消息仍在。全部使用真实 LocalProfile/ZaizuoNode，不注入假消息数据；KDF仅测试用低成本参数，不改变产品默认参数。
4. 全量应用测试还包括已存在的双资料本地 bare Git 入驻与文字互通、媒体加密读取、宽窄布局和启动恢复。最终数量及 Windows 构建回执见交付说明。
